# YemenBook — حزمة handoff التقنية لمزود الدفع

## الغرض

هذه الحزمة موجهة إلى فريق الشراكات أو التاجر لدى بنك الكريمي أو محفظة جوالي أو محفظة جيب. لا تتضمن مفاتيح أو كلمات مرور أو أرقام حسابات. الغاية منها طلب معلومات التكامل الرسمية اللازمة لتفعيل الدفع من خادم YemenBook بصورة قابلة للتدقيق.

## وصف المنتج المختصر

YemenBook شبكة اجتماعية تبدأ من اليمن. تتضمن، عند الاعتماد، متجر صفحات، حملات إعلانية، اشتراكات منشئين، ونجوم وأرباح منشئين. حالياً جميع هذه الوظائف محاكاة ومحجوبة عن التنفيذ الحي.

## نطاق التكامل المطلوب

| القدرة | سؤال موجّه للمزود | حالة YemenBook الحالية |
|---|---|---|
| إنشاء عملية دفع | هل توجد API تاجر لإنشاء طلب دفع باسم المتجر وتحديد المبلغ والمرجع؟ | مطلوب، غير مفعّل. |
| إعادة التوجيه/QR/Deep Link | ما هو التدفق الرسمي الذي ينتقل به المستخدم من التطبيق إلى مزود الدفع ثم يعود؟ | مطلوب، غير مفعّل. |
| تأكيد العملية | ما هو webhook الرسمي، خوارزمية التوقيع، وإعادة المحاولة؟ | مطلوب، غير مفعّل. |
| الاستعلام والإلغاء | هل يمكن للخادم الاستعلام عن العملية أو إلغاؤها قبل التسوية؟ | مطلوب، غير مفعّل. |
| الاسترداد | هل توجد API أو إجراء تشغيلي لاسترداد العملية؟ | مطلوب، غير مفعّل. |
| التسوية | ما هي دورة التسوية والرسوم والحدود والتقارير؟ | مطلوب، غير مفعّل. |
| سحب الأرباح | هل توجد مدفوعات صادرة أو API صرف للتاجر؟ | مطلوب، غير مفعّل. |

## متطلبات الأمن

يجب أن تُرسل بيانات الاعتماد إلى فريق YemenBook عبر قناة إعدادات آمنة فقط بعد توقيع الاتفاقية. لا تُضمَّن في التطبيق ولا في البريد العام. يحتاج اليمن بوك إلى إجابة رسمية عن العناصر التالية:

| البند | المطلوب |
|---|---|
| المصادقة | نوع المفاتيح، تدويرها، نطاقاتها، ومدة صلاحيتها. |
| التوقيع | خوارزمية توقيع webhooks وتحقق timestamp والحماية من إعادة التشغيل. |
| الاختبار | بيئة Sandbox أو حساب تاجر اختباري وبيانات نجاح وفشل موثقة. |
| idempotency | حقل مرجع فريد وطريقة التعامل مع إعادة المحاولة أو طلب مكرر. |
| القوائم المسموح بها | عناوين IP أو نطاقات webhook اللازمة، إن وجدت. |
| الاستجابة للحوادث | قناة عاجلة لتعليق الحساب أو إيقاف المدفوعات عند الاشتباه. |

## مخطط التدفق المستهدف

1. ينشئ تطبيق YemenBook طلباً موقّعاً إلى خادم YemenBook، وليس إلى مزود الدفع مباشرة.
2. يتحقق الخادم من المستخدم والسعر والسلعة وحالة المنطقة، وينشئ مرجعاً idempotent في دفتر الأستاذ.
3. يطلب الخادم جلسة الدفع من API التاجر، ثم يعيد للتطبيق رابطاً أو رمزاً آمناً قصير الأجل.
4. يكمل المستخدم التفويض لدى المزود.
5. يتحقق خادم YemenBook من webhook الموقّع والاستعلام الخادمي قبل اعتماد الطلب.
6. يسجل الخادم النتيجة ويحدّث حالة المتجر أو الإعلان أو الاشتراك. لا تغير الواجهة الرصيد بمفردها.

## معايير القبول قبل التفعيل

لا ينقل المزود إلى حالة `live` إلا بعد نجاح الاختبارات في Sandbox أو البيئة التي يوافق عليها المزود، وتشمل الدفع الناجح، الرفض، الإلغاء، تكرار الطلب، webhook متأخر، webhook مكرر، الاسترداد، انقطاع الشبكة، ومراجعة سجل التدقيق.

## بيانات الاتصال المطلوبة من المزود

نحتاج اسم فريق التكامل، قناة دعم تقنية، ساعات التغطية، وإجراء طلب حساب تاجر. لا نحتاج بيانات اعتماد في هذه الوثيقة أو عبر المحادثة.
