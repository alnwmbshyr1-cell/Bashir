# YemenBook — قائمة تحقق تشغيل مزود الدفع

## قاعدة المنع

لا تتغير حالة أي مزود من `locked` إلى حالة اختبار أو إنتاج إلا بقرار موثق من مسؤول الأعمال، ومسؤول الأمن، ومسؤول العمليات، وبعد توقيع اتفاقية تاجر واستلام وثائق API الرسمية.

## قبل الاختبار

| الفحص | المالك | حالة الاعتماد |
|---|---|---|
| اتفاقية تاجر وحساب أعمال مفعل | الأعمال | مطلوب |
| وثيقة API رسمية وبيئة Sandbox | التكامل | مطلوب |
| أسرار مزود مخزنة في مدير أسرار خادمي فقط | الأمن | مطلوب |
| سياسة خصوصية وشروط واسترداد ونزاعات منشورة | القانون/المنتج | مطلوب |
| مخطط دفتر الأستاذ والعمولات والتسوية | المالية/الهندسة | مطلوب |
| سياسة KYC/AML وحظر وتجميد للمستخدمين عند السحب | المخاطر | مطلوب |
| مفاتيح إيقاف للدفع والسحب مستقلة عن تطبيق الجوال | العمليات | مطلوب |

## سيناريوهات الاختبار

| السيناريو | النتيجة المقبولة |
|---|---|
| دفع ناجح | لا يعتمد الطلب إلا بعد تحقق خادمي من webhook أو استعلام رسمي. |
| دفع مرفوض أو ملغى | يبقى الطلب غير مدفوع ولا يحجز رصيداً أو منتجاً نهائياً. |
| طلب مكرر | المرجع idempotent يمنع خصماً أو تسجيلاً مزدوجاً. |
| webhook مكرر أو متأخر | يعالج مرة واحدة مع سجل زمني وتوقيع موثّق. |
| فشل شبكة العميل | يمكن استعلام الخادم عن الحالة ولا تقرر الواجهة النجاح. |
| استرداد | يتتبع المرجع الأصلي ويغير دفتر الأستاذ بعد تأكيد المزود. |
| اكتشاف احتيال | تجمد العملية وتصل تنبيه للعمليات ولا تنفذ دفعة صادرة. |
| إيقاف طارئ | تمنع مفاتيح الإيقاف إنشاء عمليات جديدة فوراً من الخادم. |

## الدخول المحدود إلى الإنتاج

يبدأ الإطلاق بحدود كمية ومستخدمين محدودين، مع مراقبة يومية للتسوية والأخطاء والاعتراضات. يبقى سحب أرباح المنشئين مغلقاً في البداية حتى تتكرر تسوية المدفوعات بنجاح وتوافق فرق المخاطر والمالية على مسار المدفوعات الصادرة.

## سجل قرار الإطلاق

يوثق كل قرار باسم المزود، رقم نسخة API، بيئة الاختبار، تاريخ الاختبار، المسؤولين الموافقين، حالة مفاتيح الإيقاف، وأي استثناءات. لا يعد هذا السجل بديلاً عن المستندات القانونية أو اتفاقية المزود.
