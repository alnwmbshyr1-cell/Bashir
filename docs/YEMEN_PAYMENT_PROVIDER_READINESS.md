# YemenBook — جاهزية مزودي الدفع في اليمن

## النطاق

سجّل مالك المشروع ثلاثة مزودين محليين مرشحين: **محفظة جوالي**، و**بنك الكريمي**، و**محفظة جيب**. هذه الوثيقة لا تعني أن أي تكامل نشط أو أن أي حساب أعمال قائم؛ إنها تفصل ما أمكن تأكيده من الصفحات الرسمية وما ما زال يحتاج تواصلاً واعتماداً مباشرين مع كل مزود.

| المزود | ما أمكن تأكيده علناً | حالة وثائق API للتاجر في المصادر المسترجعة | قرار YemenBook الحالي |
|---|---|---|---|
| بنك الكريمي | يعرض البنك خدمة «الربط API» لربط تطبيق أو موقع بالمصرف لتسهيل الدفع للعملاء. [1] | لم تُعرض مواصفات endpoints أو طريقة توقيع أو sandbox أو إجراءات onboarding العامة في الصفحة المسترجعة. | **مرشح أول**؛ مقفل إلى حين توقيع اتفاقية التاجر واستلام الوثائق الرسمية. |
| محفظة جوالي | يعرض الموقع الرسمي خدمات المحفظة ونموذج «كن وكيلاً» وشركاء محليين. [2] | لم يُسترجع مرجع API أو بوابة تاجر عامة من الصفحة الرسمية. | **مرشح**؛ لا يُبنى أي اتصال قبل الحصول على وثائق تاجر مكتوبة من جوالي. |
| محفظة جيب | يعرض الموقع الرسمي تطبيق المحفظة والشحن والسداد وخدمة العملاء. [3] | لم يُسترجع مرجع API أو بوابة تاجر عامة من الصفحة الرسمية. | **مرشح**؛ لا يُبنى أي اتصال قبل الحصول على وثائق تاجر مكتوبة من جيب. |

## متطلبات التاجر التي يجب التحقق منها

في حالة بنك الكريمي، تنص الأسئلة الشائعة الرسمية على أن طلب نقطة «حاسب» لقبول الدفع في النشاط التجاري يحتاج عنواناً فعلياً دائماً للنشاط، وحساباً باسم النشاط لدى البنك، وزيارة فرع لتوقيع اتفاقية الخدمة. [4] لا يكفي ذلك وحده لتأكيد API لخدمة YemenBook، لكنه يدل على أن اعتماد التاجر واتفاقية الخدمة جزء من المسار الرسمي.

| بند مطلوب من كل مزود | لماذا يلزم |
|---|---|
| اتفاقية تاجر أو حساب أعمال | لتحديد صاحب الحساب والمخاطر والتسويات والمسؤوليات. |
| وثيقة API رسمية | لتأكيد مسارات الإنشاء، الاستعلام، الإلغاء، الاسترداد، التوقيع، والحدود. |
| بيئة Sandbox أو حساب اختبار | لاختبار الدفع بلا أموال حقيقية قبل الإطلاق. |
| مواصفات webhook موقّعة | لتأكيد النجاح أو الفشل من الخادم، وليس من الهاتف. |
| جدول الرسوم والتسوية والنزاعات | لحساب عمولة المتجر 5% وأرباح المنشئين والاستردادات بدقة. |
| آلية المدفوعات الصادرة أو السحب | لتقييم إمكان دفع أرباح المنشئين أو الحد الأدنى 100 دولار. |
| متطلبات KYC/AML والحماية من الاحتيال | لتطبيق قواعد الأهلية والسحب والمراجعة. |

## قاعدة التكامل

حتى بعد استلام الوثائق، لا تحفظ مفاتيح المزود في تطبيق الهاتف ولا تقرر الواجهة أن الدفع نجح. ينشئ الخادم الطلب، يتحقق من webhook موقّع، ويسجل النتيجة في دفتر الأستاذ قبل تغيير أي رصيد أو طلب أو حالة سحب.

## الخطوة التالية

يرسل مالك المشروع طلب تاجر إلى كل مزود، ثم يزوّد الفريق باسم المزود الذي وافق على التكامل ونسخة وثائق API غير السرية. بعد ذلك فقط يمكن طلب القيم الحساسة عبر واجهة إعدادات محمية، ثم بناء الموصل الخادمي المناسب.
